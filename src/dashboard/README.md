# Gas Shadow 대시보드 (탭 4개)

배포: <https://gas-shadow-production.up.railway.app/>

상단 탭 4개: **실시간 관제**(3D 조선소 + 구역 상태 + 안전 에이전트) · **작업허가 검토**(접수된 허가서 → AI 사전 검토 → 관리자 결정) · **안전 일지**(사건·조치 타임라인 + 일일 보고서) · **작업자 관리**(출입 인원·위치).

- 센서는 모든 밀폐구역에 상시 부착된 것으로 본다. 수동 측정은 측정요원을 호출해서 한다
- 작업허가 검토의 AI 판정·근거, 에이전트 분석 결과는 모두 미리 적어 둔 합성값이다 (실제 RAG·모델 출력이 아님)
- 작업자 이름·회사·연락처, 허가서, 사고 판례는 모두 연출용 가상 값이다

## 내 컴퓨터에서 실행하기

### 1. 준비물 (처음 한 번)

- **Node.js 20.19 이상 또는 22.12 이상** (LTS 버전 권장). 터미널에서 `node -v`로 확인한다
  - 없거나 낮으면 <https://nodejs.org>에서 LTS를 받아 설치한다. nvm을 쓰면 `nvm install --lts`
  - npm은 Node.js에 같이 들어 있다
- **Git**
- **브라우저**: Chrome 또는 Edge 최신판 (3D가 WebGL을 쓴다)

### 2. 코드 받기

```bash
git clone https://github.com/gksgPdls/GasShadow.git
cd GasShadow
```

### 3. 설치하고 켜기

```bash
cd src/dashboard
npm install        # 처음 한 번, 또는 package.json이 바뀌었을 때 (1~2분)
npm run dev
```

터미널에 `Local: http://127.0.0.1:8732/`이 뜨면 브라우저에서 **<http://localhost:8732>**를 연다. 끌 때는 터미널에서 `Ctrl + C`.

- `npm install` 중 `npm warn install-scripts ...` 경고는 무시해도 된다 (macOS 파일 감시용 선택 패키지)
- 인터넷은 `npm install` 때만 필요하다. 폰트·three.js가 모두 패키지에 들어 있어서 켠 뒤에는 오프라인에서도 열린다
- 코드를 고치면 브라우저가 자동으로 새로 그린다

### 4. 발표·시연할 때

| 주소 | 용도 |
|---|---|
| `http://localhost:8732/?start=0900&demo=0` | 09:00부터 재생. 약 1분 안에 송풍기 정지 → 경계 → 09:10 법정 초과 → 09:13 측정요원 도착 |
| `http://localhost:8732/?start=0912` | 경보가 난 직후(09:12)부터. 맨 아래 데모 제어 띠로 일시정지·재생 속도·처음부터·통신 장애를 조작 |
| 주소 끝에 `#/prep` · `#/history` · `#/workers` | 작업허가 검토 · 안전 일지 · 작업자 관리 탭으로 바로 열기 |

### 5. 잘 안 될 때

| 증상 | 해결 |
|---|---|
| `Port 8732 is already in use` | 이미 켜 둔 게 있으면 그 터미널에서 끈다. 다른 포트로 켜려면 `npm run dev -- --port 5173` |
| `npm: command not found` / `node -v`가 20.19보다 낮음 | Node.js LTS를 새로 설치하고 터미널을 다시 연다 |
| 3D 자리에 "3D를 표시할 수 없습니다" | Chrome/Edge 설정 → 시스템 → **그래픽 가속 사용** 켜기. 그래도 안 되면 다른 브라우저 |
| 같은 와이파이의 다른 기기(태블릿 등)에서 보고 싶음 | `npm run dev -- --host` 로 켜고, 다른 기기에서 `http://<이 컴퓨터 IP>:8732` |
| 원격 맥에서 켜 둔 걸 노트북에서 보고 싶음 | 노트북에서 `ssh -N -L 8732:127.0.0.1:8732 <사용자>@<맥 주소>` 를 켜 둔 채 `http://localhost:8732` |
| 화면이 이상하게 멈춤 | 새로고침. 결정 기록·입력값은 메모리에만 있어서 새로고침하면 처음으로 돌아간다 |

### 그 밖의 명령

- `npm run build`: 배포용 파일을 `dist/`에 만든다. `npm run preview`로 같은 포트에서 연다
- `npm run lint`: 코드 검사 (oxlint)

URL 옵션 (프로토타입과 같음)

- `?start=0912`: 시작 시각 (기본 09:00)
- `?stage=outfit`: 3D를 해당 공정 가까이에서 시작 (`all` · `assembly` · `outfit` · `paint` · `pe` · `erect`)
- `?block=B-D23`: 블록을 고른 채 시작
- `?demo=0`: 맨 아래 데모 제어 띠를 숨긴다 (발표 화면용)
- 탭은 주소 끝 `#/today` · `#/prep` · `#/history` · `#/workers` (예: `/?start=0912&demo=0#/history`)
- 관리자 결정 기록·입력값은 메모리에만 있어서 새로고침하면 처음으로 돌아간다

| 자리 | 내용 | 파일 |
|---|---|---|
| 맨 위 | 탭 · 시각 | `components/TopNav.tsx` |

| 가운데 | ③ 블록 현황: 3D + 현장 이벤트 카드 + 블록 카드 한 줄 (측정기가 있는 블록만, 문제 있는 블록부터 · 옆으로 넘김) | `components/BlockBoard.tsx`, `Yard3D.tsx`, `EventFeed.tsx` |

- 왼쪽 항목·블록 카드·3D의 블록이나 구역 부피를 누르면 3D가 그 블록으로 가고, 왼쪽에 구역 상세가 열린다: 지금 값(크게), 최근 40분 그래프(경계·법정 기준선, 지금 추세면 법정 기준까지 예측선), 5가스, 환기·센서·현장 인력, 측정요원 호출 · 작업책임자에게 지시, 이 구역 이벤트
- 현장에서 일어난 일은 사건·조치 로그에 모두 남기고, 3D 위에는 최근 5분 안의 위험한 일(법정 초과 · 무허가 의심 · 센서 결측 · 경계) 1건만 카드로 띄운다. 3D 위 글씨는 공정 이름과 문제가 생긴 칸 이름표만 남겼다 (`data/scenario.ts`의 `TIMELINE` + 상태 변화). 경계선 근처 깜박임은 1분 이어질 때만 알린다
- 측정요원은 호출하면 시뮬레이션 시각으로 이동해 도착한다 (5분, 가정)
- 작업책임자(담당반장)는 위험작업 중 현장에 상주하므로 부르지 않는다 (가정). [작업책임자에게 지시]는 무전 지시로 보고, 법정 초과면 '작업 중지·대피', 아니면 '작업 상태 확인'. 응답은 관제 관리자가 입력한다 (지시 전달 → 응답 확인 → 대피 완료, 결정 #12). 지시할 때 작업부서 관리감독자에게 알림을 로그에 남긴다 (밀폐공간 이상 시 관리감독자에게 알리는 구조: 산업안전보건기준 규칙 제623조 ②)
- 3D는 지붕·벽·천장크레인 같은 구조물을 기본으로 숨기고 밀폐구역(상태 색 부피·테두리)이 잘 보이게 했다. 공정 바로가기 옆 [구조물 보기]로 다시 켠다. 도크·PE장 크레인은 그 공정을 가까이 볼 때만 보인다
- 서버 값이 5초 넘게 오지 않으면 3D 아래에 "마지막으로 받은 시각 기준" 안내가 뜨고, 에이전트는 '서버 끊김'으로 바뀐다 (화면 값은 지우지 않음)
- 서버(재생기)가 화면과 다른 구역 목록을 보내면 (옛 코드로 떠 있으면 대부분 칸이 '센서 결측'으로 보인다) 화면이 한 번 경고한다. 메인 서버·재생기를 이 코드로 다시 띄우면 된다
- 빨간 채움은 '경보 처리' 버튼에만 쓴다. 법정 초과 뱃지·구역 상세 띠는 연한 빨강 바탕 + 진한 빨강 글씨
- WebGL을 못 쓰면 3D 자리에 안내만 나온다 (상태는 왼쪽 목록으로 본다)
- **조선소 3D (1 단위 = 1 m)**: 공장 줄(대조립 · 선행의장 · 선행도장 · PE장) + 큰길 + 도크(배 2척, 골리앗 2기) + 안벽(진수 후 의장 중인 배). 공장은 베이 2개, 바닥에 작업 단계 이름(배재 · 취부 · 용접 · 사상·검사 / 블라스팅 · 도장 셀 / 세팅 → 탑재 대기)
- **블록 안 칸 = 감시 단위**: 블록마다 실제 치수로 안쪽 칸막이(플로어 3프레임 2.58 m 간격, 거더, 스트링거·데크)를 그리고, 칸막이마다 맨홀(SOLAS 600 × 800 mm)을 뚫었다 (블록 16개 · 칸 112개).
  - **측정기는 오늘 작업이 있는 칸과 그 칸에 맞닿은 칸(인접 공간)에만** 붙는다 (54대, OSHA 1915.12 공간 + 인접 공간 측정). 나머지 칸은 측정기 없이 회색 윤곽만 그린다
  - 색은 **그 칸에만** 칠한다. 작업 칸은 옅은 초록, 인접 칸은 거의 투명, 문제가 생긴 칸만 진하게. 블록 이름표·블록 카드도 블록 전체가 아니라 "어느 칸이 무슨 상태인지"를 말한다
  - 도둑작업 시연: 도장 중인 '3번 밸러스트탱크(우현) 4번 칸' 옆의 '파이프덕트 3 2번 칸'(오늘 허가 없음, 인접 칸이라 측정기 있음)에서 09:12부터 CO가 오른다. 옆 칸 도장은 LEL이 오르는데 여기서는 화기 흔적(CO)이 오르는 것이라 무허가 작업으로 본다 — 작업허가 검토의 PTW-2541-0491(PD-3 배관 관통부 용접)과 이어짐
  - 칸 이름은 쉬운 말("3번 밸러스트탱크(우현) 4번 칸")로 쓰고, 현장 약어(No.3 WBT(S))와 프레임 번호는 보조 설명에 둔다. 'n번 칸' 번호는 우리가 붙인 것이다
  - 블록·구획 데이터는 `scripts/build_site.py` → `src/data/site.json` 하나에 있고 화면(`data/scenario.ts`)과 서버 재생기(`src/server/replayer/scenario.py`)가 같이 읽는다. 기존 구역 ID(Z-D23-WBT3S 등)는 작업 중인 구획의 ID로 그대로 써서 작업허가·모델 에피소드·현장 이벤트와 이어진다
  - 송풍기·덕트·사다리·출입현황판은 **작업이 있는 구획마다** 붙는다: 바닥에 놓은 이동식 송풍기(12인치급) → 지름 0.3 m 주름 덕트 → 그 구획의 출입 개구부 → 구획 바닥 작업자 근처까지. 도장·세척 구획은 바닥에서 뽑는 배기 덕트(파란 송풍기)가 하나 더 있다. 높은 블록(사이드·코퍼댐·선수·선미)은 족장(2 m마다 발판·난간)과 사다리로 해당 층 구획 옆면 개구부로 들어간다
  - 블록을 고르면 앞면을 비스듬히 옆에서 본다 (층 구획이 보이게). 블록 카드에는 구획 수, 구역 상세 위에는 같은 블록의 구획 목록이 나온다
- **사람 (키 1.75 m)**: 작업자는 허가서 인원만큼 그 허가 구획 안을 돌아다니고, 가끔 사다리·출입구로 나와 출입현황판 앞에서 쉬었다 들어간다. 허가 시작 전에는 밖에서 기다리고, 법정 초과면 밖으로 대피한다. 감시인은 출입현황판 옆. 측정요원·관리감독자는 아래 '현장 인력'의 출동·도착을 따라 큰길로 이동한다. 사람에 마우스를 올리면 허가 번호·작업·지금 안 인원이 보인다. **위치는 모두 연출용 합성** (위치 추적 기능 아님)
- **무허가 작업 의심 (도둑작업)**: 오늘 허가가 없지만 측정기가 있는 칸(작업 칸의 인접 칸)에 작업 흔적 가스(LEL 3 %LEL · CO 8 ppm · H₂S 2 ppm · CO₂ 0.3 % 이상, O₂ 20.0 % 이하)가 잡히면 바로 '무허가 의심'(자주색)으로 띄운다: 상태 바 숫자, 왼쪽 카드, 토스트, 그 칸 색·이름표, 이벤트 카드, 로그. 시연에서는 09:12부터 '파이프덕트 3 2번 칸'의 CO가 올라 09:15에 잡힌다. 판정은 화면 `lib/sim.ts`와 서버 `rules.py`가 같다. 기준값은 근거 없는 팀 가정이다
- **블록 이름**: 화면에는 "이중저 D21"처럼 종류 + 코드로 쓴다. 내부 ID의 `B-`는 우리가 붙인 접두어라 화면에서 뺐다 (실제 블록명 예: B51S · S11P · D24S, 대한조선학회논문집 2008 · 2016. 첫 글자 뜻은 미확인)
- 실시간 관제는 다른 탭으로 가도 내리지 않고 숨겨 둔다 (3D 시점·선택 유지)

## 코드

- `src/data/scenario.ts`: 합성 데이터 (프로토타입 `data.js`에 타입만 붙임)
- `src/data/permits.ts`: 허가서 12건(와이어프레임 예시) + 비밀폐 합성 4건, AI 체크 결과, 선별 제안·최종, 구역 용적
- `src/lib/records.ts`: 관리자 결정 기록 (작업허가 검토에서 쌓고 안전 일지에서 읽음)
- `src/lib/route.ts`: `#/...` 탭 이동
- `src/pages/`: 탭별 페이지 (`TodayPage` · `review/PermitReviewPage` + `review/` · `HistoryPage` + `history/` · `WorkersPage`). `prep/`은 작업허가 검토가 같이 쓰는 데이터·부품
- `src/lib/sim.ts`: 수신 흉내·판정·우선순위·원인 문장 (프로토타입 `app.js`의 로직) + 현장 이벤트 문장·인력 호출·구역 상세
- `src/lib/useSimulation.ts`: 메인 서버가 있으면 WebSocket 값을 받고, 없으면 250 ms마다 브라우저 시뮬레이션을 진행한다 (5초마다 서버를 다시 찾음)
- `src/three/yard3d.js` · `block3d.js`: 프로토타입 3D 코드를 ES 모듈로 바꾼 것. `mountBlock3D(host)`가 `{ update, select, goto, dispose }`를 돌려준다. 이름표·패널 등 3D 위 DOM은 이 파일이 직접 만들고, 모양은 `yard3d.css`
- `src/index.css`: 색·글꼴. 상태 색(`--legal` 등)은 3D가 읽으므로 hex로 둔다. 상태 색을 바꾸면 3D 구역 색도 같이 바뀐다

## 디자인 규칙

- 위쪽 네비는 남색(`--navy`), 로고는 크림(`--cream`) + 주황(`--warn`). 본문 바탕은 거의 흰색
- 진한 색은 상태에만: 법정 초과 **빨강**(거의 뜨면 안 되는 상태) > 센서 결측 **보라** > 경계·사전 예측 **주황**(로고 주황) > 정상 **초록** > 작업 없음 회색. 색과 함께 항상 상태 단어를 쓴다
- 흰 바탕 위 주황 글씨는 `text-warn-ink`(진한 주황)를 쓴다. 점·막대·3D는 로고 주황(`--warn`)
- 파랑(`--primary`)은 링크·선택 표시에만. 주요 버튼은 남색, 경보 처리만 빨강
